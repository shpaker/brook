# Roadmap

## MVP (зафиксированный порядок)

1. **`brook-core`** — движок загрузок. Per-download `DownloadEngine` + единый `DownloadManager`. Сегменты, **чанковая запись**, ресюм, ретраи, SQLite-персистентность. Без сети — сначала на `wiremock` / локальном тест-сервере, затем с реальным HTTP.
2. **`brook-proto` + `brook-api`** — gRPC-сервер поверх `brook-core`. Контракт в `proto/brook/v1/brook.proto`, сгенерированный код в `brook-proto`, сервер (`tonic`) в `brook-api`. Слушает loopback.
3. **Конфигурация — TOML.** Читается «из-под ног» — `./brook.toml` в текущей рабочей директории. Если нет — создаётся с дефолтами при старте, путь пишется в stderr. В MVP API-методов на settings нет — редактирование файла вручную.
4. **`brook`** — ratatui-клиент (крейт и бинарь называются одинаково). В MVP это единственный UI и единственный бинарь. При запуске:
   - читает TOML-конфиг из CWD,
   - поднимает `DownloadManager` и `brook-api` внутри своего процесса,
   - рендерит ratatui-UI, который является gRPC-клиентом к локальному серверу.

## Почему такой порядок (зафиксировано)

- **Движок — первым.** Всё остальное — обёртки вокруг него.
- **API — вторым классом, а не надстройкой.** Даже в MVP, когда сервер и клиент в одном процессе, между ними только gRPC. Это гарантирует, что завтра мы разделим процессы без рефакторинга клиента.
- **TOML — минимальный путь к персистентным настройкам.** Settings-методы API добавляются позже, когда UI дорастёт до интерактивного управления настройками.
- **Ratatui — быстрый путь к рабочему UI.** Клавиатура, TUI-эстетика, никаких нативных интеграций. Проверяет API руками на реальном клиенте.
- **egui откладывается.** Трей, глобальный шорткат, нативное окно — большой пласт macOS-специфичной работы, не вписывается в «минимально полезный продукт».

## Явные переоценки относительно первой версии доков

- Ранее: egui-клиент, трей, глобальный шорткат и клик-развёртка были в MVP. → Перенесено в [post-mvp.md](post-mvp.md).
- Ранее: ratatui был отвергнут в пользу egui. → Возвращён в MVP как основной клиент (крейт и бинарь — `brook`).
- Ранее: выделенный демон — Later. Подтверждено: в MVP демона нет, `brook` всё-в-одном.
- Ранее: Settings через gRPC-методы в MVP. → Перенесено; в MVP настройки читаются из TOML при старте.
- Ранее: TOML-конфиг в `~/Library/Application Support/brook/`. → В MVP — из CWD (`./brook.toml`); стандартный путь — Post-MVP.
- Ранее: платформа — «текущая + 1 назад». → Только самая свежая релизная macOS.
