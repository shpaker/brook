# Roadmap

## MVP (зафиксированный порядок)

1. **`brook-core`** — движок загрузок. Per-download `DownloadEngine` + единый `DownloadManager`. Воркеры, **покусочная запись**, ресюм, ретраи, SQLite-персистентность. Без сети — сначала на `wiremock` / локальном тест-сервере, затем с реальным HTTP.
2. **`brook-proto` + `brook-api`** — gRPC-сервер поверх `brook-core`. Контракт в `proto/brook/v1/brook.proto`, сгенерированный код в `brook-proto`, сервер (`tonic`) в `brook-api`. Слушает loopback.
3. **Конфигурация — в БД.** Таблица `settings` внутри `./brook.db`. На первом старте демон сидит её дефолтами. TOML-файлов нет. API-методов на settings в MVP тоже нет — правка через SQL на остановленном демоне.
4. **`brookd`** — бинарь-демон: берёт single-instance lock, открывает `brook.db`, поднимает `DownloadManager` и `brook-api`. UI не содержит. Обязательная отдельная процесс-граница между движком и клиентом уже с MVP.
5. **`brook-tui`** — крейт с ratatui-клиентом (бинарь называется `brook`). gRPC-клиент к `brookd` на `127.0.0.1:<port>` (флаг `--port`, дефолт 7090). Если демон не запущен — сообщение и выход.

## Почему такой порядок (зафиксировано)

- **Движок — первым.** Всё остальное — обёртки вокруг него.
- **API — вторым классом, а не надстройкой.** С MVP клиент и сервер — это два разных процесса. gRPC — единственный способ обратиться к движку, никаких «коротких путей» даже локально.
- **Демон отдельно от UI.** `brookd` — единственный процесс, который трогает `brook.db` и целевые файлы. Клиентов можно запускать сколько угодно, переподключать, закрывать — демон продолжает работать.
- **Настройки — в БД с первого дня.** TOML-парсер не нужен: БД уже есть для очереди, settings-таблица — это ещё одна таблица. Settings-методы API добавляются позже, когда UI дорастёт до интерактивного управления.
- **Ratatui — быстрый путь к рабочему UI.** Клавиатура, TUI-эстетика, никаких нативных интеграций. Проверяет API руками на реальном клиенте.
- **egui откладывается.** Трей, глобальный шорткат, нативное окно — большой пласт macOS-специфичной работы, не вписывается в «минимально полезный продукт».

## Явные переоценки относительно первой версии доков

- Ранее: egui-клиент, трей, глобальный шорткат и клик-развёртка были в MVP. → Перенесено в [post-mvp.md](post-mvp.md).
- Ранее: ratatui был отвергнут в пользу egui. → Возвращён в MVP как основной клиент (крейт `brook-tui`, бинарь `brook`).
- Ранее: в MVP демона нет, `brook` всё-в-одном. → Пересмотрено: в MVP уже `brookd` + `brook`, два процесса.
- Ранее: Settings через gRPC-методы в MVP. → Перенесено в post-MVP; в MVP настройки читаются из таблицы `settings` БД при старте.
- Ранее: TOML-конфиг в CWD (`./brook.toml`). → TOML убран; конфиг полностью в `./brook.db`.
- Ранее: платформа — «текущая + 1 назад». → Только самая свежая релизная macOS.
