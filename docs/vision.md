# Vision

## Что это
**brook** — менеджер закачек для macOS с TUI-эстетикой и клавиатурным управлением. Архитектурно — сервис с gRPC API (в духе Transmission), над которым живут разные клиенты. В MVP — ratatui-клиент в терминале. Что идёт дальше — см. [post-mvp.md](post-mvp.md).

## Целевой пользователь
Технический пользователь, который живёт в терминале и ценит предсказуемость шорткатов. Хочет аккуратный менеджер закачек, который умеет паузы, ресюм и сегментированную загрузку, и которым можно управлять как локально из TUI, так и (в будущем) удалённо через gRPC-API.

## Принципы
- **Клавиатура — primary.** MVP — ratatui, терминал.
- **API — единственный путь к движку.** Все клиенты (текущие и будущие) говорят с ядром через gRPC. Никаких «коротких путей» в обход API.
- **Движок — библиотека.** `brook-core` не зависит от UI и API — переиспользуемый кирпич.
- **TUI-эстетика.** В MVP она буквальна: ratatui прямо в терминале, без нативного окна.
- **Константный RAM-бюджет на задачу.** Загрузка идёт чанками; память процесса не растёт от размера файла.

## Анти-цели
- Не превращаемся в «ещё один браузерный менеджер с сотней настроек».
- Не пишем свой торрент-движок (см. features.md — вне скоупа).
- Не пытаемся заменить `yt-dlp` — интегрируемся при необходимости (см. [post-mvp.md](post-mvp.md)).
- В MVP не делаем кросс-платформенность — только macOS. Но архитектурно не закрываемся.

## Ключевые решения (зафиксировано)
- Порядок реализации: `brook-core` → `brook-proto` + `brook-api` → settings в БД → `brookd` (демон) → `brook-tui` (ratatui-клиент, бинарь `brook`). См. [roadmap.md](roadmap.md).
- Всё, что после MVP, — в [post-mvp.md](post-mvp.md).
