# Открытые вопросы

После третьего раунда требований. Закрытые вопросы перенесены в соответствующие docs и здесь не повторяются.

## Конфигурация
1. **Имя файла конфига «из-под ног»** — `./brook.toml` или `./config.toml`?
   _Лин: `brook.toml` — самодокументирующее имя, одно слово, не путается с `config.toml` других проектов в той же папке._

## Скоуп Post-MVP
2. **Приоритеты после MVP** — `brook-app` идёт первым (зафиксировано). Что второе?
   - Выделение `brookd` + `--connect` для удалённого доступа,
   - Auth + TLS для gRPC,
   - Стандартный путь конфига (`~/Library/Application Support/brook/config.toml`),
   - Clipboard monitor,
   - Лимит скорости.
   _Лин: `brookd` + auth + TLS → открывают remote-сценарий, ради которого и был нужен API._

## Качество
3. **MVP quality gate** — сценарии, которые прогоняем руками до «готово»:
   - большой файл (>1 GB) с паузой и перезапуском приложения (ресюм);
   - отмена с очисткой частичного файла;
   - 10 задач одновременно, проверка лимита параллельности;
   - потеря сети → автоматический ретрай → восстановление;
   - два клиента одновременно (`brook` + `grpcurl`) видят одно состояние;
   - сервер без Range → fallback на одно соединение, загрузка проходит;
   - корректный ресюм после падения процесса (kill -9 → перезапуск);
   - **пиковый RSS при 10 параллельных загрузках укладывается в бюджет** (цифра — см. #4).
   Принимаем список? Добавить ещё?
4. **RAM-бюджет** — при 10 активных загрузках какой потолок RSS считаем приемлемым?
   _Лин: ≤ 150 MB. Чанк по 64–256 KB × 10 × 4 сегмента = ~10 MB на буферы + tokio runtime + всё остальное — укладываемся с запасом._
5. **Ротация логов** — по размеру или по дням? Сколько сессий храним?
   _Лин: последние 10 сессионных файлов (`brook-<session_id>.jsonl`), каждый до 50 MB, потом ротация по размеру с суффиксом `.1`, `.2` и т.д._

## UX (Post-MVP, egui)
6. **Глобальный шорткат** — `Opt+Cmd+D` как в эскизе, или менее конфликтный `Ctrl+Opt+D`?
   _Лин: `Opt+Cmd+D`, настраивается в preferences._
